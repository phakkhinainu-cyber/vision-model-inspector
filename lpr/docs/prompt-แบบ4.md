# Prompt สร้างโปรแกรมตรวจป้ายทะเบียนรถ (แบบ 4)

Oct 16, 2026 · @Glass

## วิธีใช้ prompt นี้

คัดลอกกล่อง prompt ในหัวข้อถัดไปทั้งกล่อง ไปวางในเครื่องมือเขียนโค้ดด้วย AI (เช่น Claude Code) บนคอม Windows เครื่องที่จะใช้ตรวจป้าย AI จะสร้างโปรแกรมให้ทีละเฟส และหยุดให้คุณทดสอบก่อนทำเฟสถัดไป

1. สร้างโฟลเดอร์ว่าง เช่น `D:\LPR-app` แล้วเปิดเครื่องมือเขียนโค้ดด้วย AI ในโฟลเดอร์นั้น
2. แก้ค่าในส่วน "ข้อมูลของฉัน" ที่ต้นกล่อง prompt ให้ตรงกับบ้านคุณ เช่น จำนวนกล้อง และกล้องตัวไหนเป็นทางเข้าหรือทางออก
3. วาง prompt ทั้งกล่อง แล้วให้ AI ทำเฟส 1 ก่อน
4. เตรียมข้อมูลกล้องไว้ใกล้มือ ได้แก่ IP กล้อง ชื่อผู้ใช้ รหัสผ่าน และลิงก์ RTSP ซึ่งดูได้จากคู่มือหรือแอปของกล้อง
5. จบแต่ละเฟสให้ลองใช้จริง ถ้ามีปัญหาก็พิมพ์บอก AI เป็นภาษาไทยได้เลย เช่น "ตอนกลางคืนอ่านป้ายไม่ออก"
6. หลังติดตั้งแล้ว ให้ปล่อยให้ระบบอ่านป้ายรถจริงสัก 1–2 วัน แล้วค่อยปรับค่าความไวและเวลากันบันทึกซ้ำในหน้าตั้งค่า

## Prompt (คัดลอกทั้งกล่อง)

Prompt นี้สั่งให้ AI สร้างโปรแกรมตามแบบที่ 4 แบ่งเป็น 6 เฟส มีครบทั้งการจับภาพอัตโนมัติ การอ่านป้ายไทย ฐานข้อมูลในเครื่อง แอปบนมือถือ/แท็บเล็ต และตัวติดตั้ง .exe

```text
# ข้อมูลของฉัน (แก้ในวงเล็บ [ ] ให้ตรงกับบ้านคุณ)
- คอมที่ใช้ตรวจป้าย: Windows [11] มีการ์ดจอ NVIDIA [ไม่มี / รุ่น ...]
- จำนวนกล้อง: [2] ตัว แต่โปรแกรมต้องรองรับ 1–8 ตัว
- กล้องทางเข้า: [CAM 1 ประตูหน้า]  กล้องทางออก: [CAM 2 ทางออก]  (หรือ [กล้องตัวเดียวใช้ทั้งเข้าและออก])
- กล้องเป็น IP camera ส่งภาพแบบ RTSP ยี่ห้อ/รุ่น [ถ้ารู้]
- โฟลเดอร์เก็บข้อมูล: D:\LPR\data
- ชื่อบ้าน/ที่อยู่ที่แสดงบนหน้าจอ: [ชื่อบ้าน]

# บทบาทและเป้าหมาย
คุณเป็นวิศวกรซอฟต์แวร์อาวุโสด้าน computer vision และแอปพลิเคชัน ช่วยสร้างโปรแกรม ระบบตรวจป้ายทะเบียนรถ (LPR) สำหรับบ้านพักในประเทศไทย ทำงานบนคอม Windows เครื่องเดียวตลอด 24 ชั่วโมง โปรแกรมต้อง:
1. ต่อกล้อง RTSP หลายตัว ตรวจจับรถทุกประเภทที่ผ่าน และจับภาพอัตโนมัติโดยไม่ต้องกดปุ่ม
2. อ่านป้ายทะเบียนไทยได้ทุกรูปแบบ (ตัวอักษร เลข และจังหวัด)
3. บันทึกเหตุการณ์เข้า-ออกพร้อมภาพลงฐานข้อมูลในเครื่องนี้
4. มีหน้าจอตามแบบ สมุดบันทึกเข้า-ออก (รายละเอียดด้านล่าง)
5. ดูผ่านมือถือและแท็บเล็ตแบบแอป (PWA) ได้ทั้งในบ้านและนอกบ้าน
6. ส่งมอบเป็นตัวติดตั้ง .exe ติดตั้งแล้วใช้ได้ทันที และเปิดเองเมื่อเปิดเครื่อง

# เทคโนโลยีที่ให้ใช้
- Backend: Python 3.11+, FastAPI + Uvicorn, WebSocket สำหรับอัปเดตหน้าจอแบบสด
- วิดีโอ: OpenCV หรือ PyAV อ่าน RTSP แยก process ต่อกล้อง และเชื่อมต่อใหม่อัตโนมัติเมื่อหลุด
- ตรวจจับรถ: YOLO (ultralytics) ที่เทรนจาก COCO สำหรับ car, motorcycle, bus, truck + ByteTrack ติดตามรถแต่ละคัน
- ตรวจจับป้าย: โมเดล YOLO สำหรับป้ายทะเบียน มีสคริปต์ fine-tune ด้วยภาพป้ายไทย พร้อมวิธีเก็บและติดป้ายกำกับภาพ
- อ่านตัวอักษร: PaddleOCR (PP-OCRv5) โมเดลภาษาไทย th_PP-OCRv5_mobile_rec เป็นค่าเริ่มต้น และ EasyOCR ('th','en') เป็นตัวสำรอง ทำเป็น interface ที่เปลี่ยน OCR engine ได้ เพื่อรองรับโมเดลที่ fine-tune เองหรือบริการเชิงพาณิชย์ในอนาคต
- รันโมเดลด้วย ONNX Runtime บน CPU หรือ CUDA ถ้ามีการ์ด NVIDIA โดยเลือกให้อัตโนมัติ
- ฐานข้อมูล: SQLite โหมด WAL ผ่าน SQLAlchemy + Alembic
- Frontend: React + TypeScript + Vite ข้อความภาษาไทยทั้งหมด ฝังฟอนต์ Anuphan (UI), JetBrains Mono (เวลา), Sarabun (ป้ายทะเบียน) ไว้ในโปรแกรม ไม่โหลดจากอินเทอร์เน็ต
- หน้าต่างบนคอม: pywebview เปิด UI เดียวกันเป็นหน้าต่างโปรแกรม + ไอคอนที่ system tray
- ตัวติดตั้ง: PyInstaller + Inno Setup ได้ไฟล์ LPR-Setup.exe ให้ backend รันเป็น Windows service แยกจากหน้าต่าง ปิดหน้าต่างแล้วระบบยังจับภาพต่อ
- ระบุไลเซนส์ของทุกไลบรารีใน docs/licenses.md (เช่น ultralytics เป็น AGPL-3.0)

# การจับภาพอัตโนมัติ (ส่วนสำคัญที่สุด)
ขั้นตอนต่อกล้องหนึ่งตัว:
1. ใช้ sub-stream ความละเอียดต่ำสำหรับตรวจจับ และ main-stream สำหรับภาพที่บันทึก (ถ้ากล้องมีให้ ถ้าไม่มีใช้ stream เดียว)
2. ตรวจความเคลื่อนไหวในโซน ROI ที่วาดได้ในหน้าตั้งค่าก่อน ถ้าไม่มีความเคลื่อนไหวไม่ต้องรันโมเดล เพื่อประหยัด CPU
3. มีความเคลื่อนไหวแล้วจึงตรวจจับรถด้วย YOLO และให้ track ID แต่ละคัน
4. แต่ละคัน: หาป้ายในกรอบรถ, ครอปป้าย, ปรับภาพ (แก้มุมเอียง, CLAHE, เพิ่มความคม), แล้วจึง OCR
5. โหวตผลจากหลายเฟรม เก็บ 5–15 เฟรมที่ป้ายคมที่สุด เลือกผลที่ซ้ำบ่อยและ confidence สูงสุด ให้ได้ผลเดียวต่อรถหนึ่งคัน
6. เมื่อรถข้ามเส้นเสมือนที่วาดได้ในหน้าตั้งค่า หรือเมื่อ track จบ ให้สร้างเหตุการณ์ 1 รายการ
7. บันทึกอัตโนมัติ: ภาพเต็มเฟรมที่ดีที่สุด (JPEG), ภาพครอปป้าย และคลิปสั้น 3 วินาทีก่อนถึง 5 วินาทีหลังจาก ring buffer (เปิด/ปิดได้)
8. กันบันทึกซ้ำ: ป้ายเดียวกัน กล้องเดียวกัน ภายใน [60] วินาที นับเป็นครั้งเดียว (ปรับได้)
9. รถที่อ่านป้ายไม่ได้หรือไม่มีป้าย ยังต้องบันทึกพร้อมภาพ ด้วยสถานะ อ่านไม่ได้
10. ผลที่ confidence ต่ำกว่า [0.80] ให้สถานะ รอตรวจสอบ เพื่อให้ผู้ใช้แก้ไข
11. มีปุ่ม จับภาพเดี๋ยวนี้ และ บันทึกด้วยมือ สำหรับกรณีพิเศษ
12. รองรับภาพกลางคืนจาก IR (ขาวดำ) และสลับค่าประมวลผลกลางวัน/กลางคืนอัตโนมัติตามความสว่างของภาพ

ทิศทางเข้า/ออก:
- ตั้งบทบาทกล้องแต่ละตัวได้: ทางเข้า, ทางออก, หรือ สองทาง
- กล้องสองทาง ใช้ทิศที่รถข้ามเส้นเสมือน (เช่น ขึ้น = เข้า, ลง = ออก ตั้งค่าได้)

ประเภทรถ:
- จาก YOLO: รถยนต์, รถจักรยานยนต์, รถบัส, รถบรรทุก
- จากสีป้าย (วิเคราะห์ HSV ของพื้นป้ายและตัวอักษร): พื้นขาวอักษรดำ = รถยนต์ส่วนบุคคล, อักษรเขียว = รถกระบะ/บรรทุกส่วนบุคคล, อักษรน้ำเงิน = รถตู้/รถนั่งเกิน 7 คน, พื้นเหลือง = รถรับจ้าง/แท็กซี่/รถสาธารณะ, ป้ายแดง = รถใหม่ยังไม่จดทะเบียน, ป้ายเล็ก 3 บรรทัด = รถจักรยานยนต์
- รวมผลเป็น: รถเก๋ง, รถกระบะ, รถตู้, รถจักรยานยนต์, รถบรรทุก, แท็กซี่/รับจ้าง, รถบัส, ป้ายแดง, อื่นๆ และผู้ใช้แก้ไขได้

การแยกวิเคราะห์ป้ายไทย:
- normalize: ตัดช่องว่างและขีดที่เกิน, แปลงเลขไทย ๐–๙ เป็นเลขอารบิก, แก้ตัวที่ OCR สับสนบ่อยตามตำแหน่ง (เช่น O กับ 0, I กับ 1 ในส่วนตัวเลข)
- regex อย่างน้อย:
  รถยนต์/จักรยานยนต์: ^[0-9]?[ก-ฮ]{1,2}\s?[0-9]{1,4}$  เช่น 1กข 4521, บต 7783, 1กศ 552
  รถสาธารณะ/บรรทุก: ^[0-9]{2}-[0-9]{4}$  เช่น 70-4518
  ป้ายแดงและรูปแบบอื่น: เก็บตามที่อ่านได้ และตั้งสถานะ รอตรวจสอบ
- จังหวัด: จับคู่กับรายชื่อ 77 จังหวัดด้วย rapidfuzz คะแนนขั้นต่ำ 80
- ป้ายจักรยานยนต์ 3 บรรทัด: อ่านบรรทัดบน (ตัวอักษร), กลาง (จังหวัด), ล่าง (ตัวเลข) แล้วรวมกัน
- เก็บทั้ง plate_raw (ที่อ่านได้จริง) และ plate_norm (ใช้ค้นหา)

- รถที่อยู่ในพื้นที่ตอนนี้ = เข้าแล้วยังไม่ออก ถ้าเกิน [24] ชั่วโมงให้ติดสถานะ ไม่พบการออก

# หน้าจอหลัก (แบบ 4: สมุดบันทึกเข้า-ออก)
โทนสี: พื้น #EEF1F7, การ์ดสีขาวขอบ #DDE2EE มุมโค้ง 14px, สีหลัก indigo #4338CA, ข้อความ #141A2E, ข้อความรอง #565F78, เข้า = น้ำเงิน #1D4ED8, ออก = ส้ม #C2410C

ส่วนหัว: โลโก้ + ชื่อ สมุดบันทึกเข้า-ออก + บรรทัดรอง บันทึกอัตโนมัติจากกล้อง N ตัว · เก็บไว้ในเครื่องนี้, แท็บช่วงเวลา วันนี้ / 7 วัน / 30 วัน / กำหนดเอง, ปุ่ม ส่งออก CSV, ส่งออก Excel, พิมพ์รายงาน (PDF ฝังฟอนต์ Sarabun)

จอคอม (กว้าง 1200px ขึ้นไป) แบ่ง 3 คอลัมน์:
1. ซ้าย ตัวกรอง: ค้นหาทะเบียน (ค้นบางส่วนได้), วันที่ (ปฏิทินแสดง พ.ศ.), ทิศทาง เข้า/ออก พร้อมจำนวน, ประเภทรถพร้อมจำนวน, สถานะ (สมาชิก/ผู้มาเยือน/ไม่รู้จัก/เฝ้าระวัง), กล้อง, ปุ่มล้างตัวกรอง
2. กลาง ไทม์ไลน์: จัดกลุ่มตามชั่วโมง เช่น 17:00 – 18:00 · 5 รายการ แต่ละแถวมีจุดสีตามทิศทาง, เวลา hh:mm:ss, ป้ายทะเบียน (สีอักษรและพื้นตามสีป้ายจริง), ประเภท · กล้อง, สถานะ, ป้าย เข้า/ออก รายการใหม่ขึ้นบนสุดแบบสดผ่าน WebSocket โหลดเพิ่มเมื่อเลื่อนลง คลิกแถวเพื่อเลือก
3. ขวา รายละเอียดรถที่เลือก: ภาพจากกล้อง (คลิกขยายเต็มจอ, สลับภาพเต็ม/ภาพป้าย, เล่นคลิป), ป้ายทะเบียนจำลองขนาดใหญ่, ประเภท, สถานะ, เจ้าของ, บ้านเลขที่, พบครั้งแรก, ความแม่นยำ, รายการ เข้า-ออกวันนี้ แบบคู่ เข้า เวลา → ออก เวลา · อยู่ X ชม. Y น., สถิติ 30 วัน, ปุ่ม ดูประวัติทั้งหมด, แก้ไขข้อมูลรถ, แก้ไขทะเบียนที่อ่านผิด

หน้าอื่น (เข้าจากเมนู):
- ทะเบียนรถ: จัดการรายชื่อ สมาชิก/ผู้มาเยือน/เฝ้าระวัง, เพิ่มจากเหตุการณ์ได้ในคลิกเดียว, นำเข้า/ส่งออก Excel
- กล้อง: ดูภาพสด, เพิ่ม/แก้ RTSP, ปุ่มทดสอบการเชื่อมต่อ, วาด ROI และเส้นเสมือนบนภาพ, ตั้งบทบาทเข้า/ออก
- รอตรวจสอบ: คิวรายการที่ confidence ต่ำหรืออ่านไม่ได้ แก้เร็วด้วยคีย์บอร์ด
- รายงาน: สรุปรายวัน/รายเดือน, กราฟจำนวนเข้า-ออกรายชั่วโมง, รถที่อยู่นานผิดปกติ
- ตั้งค่า: เกณฑ์ confidence, เวลากันซ้ำ, ระยะเก็บภาพ, ที่เก็บข้อมูล, ผู้ใช้, การแจ้งเตือน, การสำรองข้อมูล

ขนาดจอ:
- แท็บเล็ต (768–1199px): ตัวกรองซ่อนเป็นแถบเลื่อนออก เหลือ 2 คอลัมน์
- มือถือ (ต่ำกว่า 768px): รายการเต็มจอ แตะแล้วเปิดรายละเอียดเป็นหน้าใหม่ ปุ่มสูงอย่างน้อย 44px
- ทุกช่องมี label, ความต่างสีข้อความอย่างน้อย 4.5:1, ใช้คีย์บอร์ดได้ครบ

# มือถือและแท็บเล็ต (PWA)
- backend เปิดเว็บที่พอร์ต [8765] ในวง LAN และทำ UI เดียวกันเป็น PWA (manifest, service worker, ไอคอน, ชื่อแอป LPR บ้าน) ติดตั้งลงหน้าจอหลักของ Android, iPhone และ iPad ได้
- PWA ต้องใช้ HTTPS: ใช้ Tailscale เป็นวิธีหลัก (tailscale serve ให้ HTTPS และดูนอกบ้านได้โดยไม่ต้องเปิดพอร์ตเราเตอร์) มี self-signed certificate เป็นทางเลือกสำหรับใช้ในบ้าน และเขียนคู่มือทีละขั้นภาษาไทยไว้ที่ docs/mobile-setup.md
- ห้ามเปิดพอร์ตจากอินเทอร์เน็ตเข้าคอมโดยตรง
- ล็อกอินด้วยชื่อผู้ใช้และรหัสผ่าน จำเครื่องได้ 30 วัน สิทธิ์ admin (แก้ไขได้) และ viewer (ดูอย่างเดียว)
- หน้าบนมือถือ: รายการล่าสุดแบบสด, ค้นหาทะเบียน, รถที่อยู่ในพื้นที่ตอนนี้, รายละเอียดพร้อมภาพ, แก้ไขทะเบียน (เฉพาะ admin)
- ส่งภาพย่อก่อน แตะแล้วจึงโหลดภาพเต็ม เพื่อประหยัดเน็ตมือถือ
- แจ้งเตือนเมื่อพบรถ ไม่รู้จัก, เฝ้าระวัง หรือรถอยู่เกินเวลาที่ตั้ง: Web Push (VAPID) เป็นหลัก และมี Telegram Bot กับ LINE Messaging API เป็นตัวเลือก (ห้ามใช้ LINE Notify เพราะปิดบริการแล้ว)

# ความปลอดภัย
- เก็บรหัสผ่านกล้องแบบเข้ารหัสผ่าน Windows Credential Manager (keyring)
- ทุก API ต้องล็อกอิน ยกเว้นหน้าล็อกอิน และจำกัดจำนวนครั้งที่ล็อกอินผิด
- บันทึก audit log ทุกการแก้ไข ลบ และส่งออกข้อมูล
- ข้อมูลทั้งหมดอยู่ในเครื่องนี้ ไม่ส่งออกนอกเครื่อง ยกเว้นการแจ้งเตือนที่ผู้ใช้เปิดเอง

# ประสิทธิภาพ
- ใช้ CPU อย่างเดียว (Core i5 รุ่นที่ 10 ขึ้นไป) ต้องรองรับ 2 กล้อง ถ้ามีการ์ด NVIDIA ต้องรองรับ 4–8 กล้อง

- เก็บ log แบบหมุนเวียนที่ D:\LPR\logs

# แผนงาน (ทำทีละเฟส จบแต่ละเฟสให้หยุด สรุปสิ่งที่ทำ และบอกวิธีทดสอบ)
เฟส 1: โครงโปรเจกต์, ต่อกล้อง RTSP, หน้าดูภาพสด, โหมดจำลองที่ใช้ไฟล์วิดีโอแทนกล้องได้
เฟส 2: ตรวจจับรถและป้าย, OCR ไทย, โหวตหลายเฟรม, จับภาพอัตโนมัติ, บันทึกลงฐานข้อมูล, สคริปต์วัดความแม่นยำกับโฟลเดอร์ภาพตัวอย่าง, สคริปต์เก็บภาพป้ายจากกล้องจริงไว้ fine-tune
เฟส 3: หน้าจอแบบ 4 ครบ (ตัวกรอง, ไทม์ไลน์สด, รายละเอียด, แก้ไข, ส่งออก CSV/Excel/PDF)
เฟส 4: หน้าทะเบียนรถ, กล้อง (วาด ROI และเส้น), รอตรวจสอบ, รายงาน, ตั้งค่า, ผู้ใช้
เฟส 5: PWA มือถือ/แท็บเล็ต, ล็อกอิน, Web Push และ Telegram, คู่มือ Tailscale
เฟส 6: ตัวติดตั้ง .exe, Windows service, เปิดเองตอนบูต, สำรองข้อมูล, คู่มือผู้ใช้ภาษาไทย
```

## อุปกรณ์ที่ต้องเตรียมนอกจากโปรแกรม

นอกจากโปรแกรม ต้องมีกล้อง IP ที่เห็นป้ายชัด คอมที่เปิดไว้ตลอด และสาย LAN ถึงกล้อง สิ่งที่มีผลต่อความแม่นยำมากที่สุดคือการติดตั้งกล้องให้ถูกมุม ซึ่งสำคัญกว่าตัวโปรแกรมเสียอีก

| อุปกรณ์ | สเปกที่แนะนำ | ใช้ทำอะไร | ความจำเป็น |
| --- | --- | --- | --- |
| กล้อง IP สำหรับอ่านป้าย (จุดละ 1 ตัว) | ส่งภาพแบบ RTSP, 2MP (1080p) ขึ้นไป, เลนส์ซูมได้ (varifocal) 2.8–12 mm, มี IR และ WDR, ตั้งชัตเตอร์ได้ 1/1000 วินาทีขึ้นไป หรือมีโหมด LPR | ถ่ายป้ายทะเบียน | จำเป็น |
| คอมสำหรับตรวจป้าย | Windows 10/11 64-bit, Core i5 รุ่น 10 ขึ้นไป หรือ Ryzen 5, RAM 16 GB, SSD 512 GB + HDD 1–2 TB เก็บภาพ, การ์ด NVIDIA ถ้าใช้กล้องเกิน 2 ตัว | รันโปรแกรมและเก็บข้อมูล | จำเป็น |
| สาย LAN Cat6 แบบภายนอก + กล่องกันน้ำ | เส้นละไม่เกิน 100 m | ต่อกล้องกับคอม (ไม่แนะนำให้กล้องใช้ Wi-Fi เพราะภาพกระตุกและหลุดบ่อย) | จำเป็น |
| PoE switch | จำนวนพอร์ต PoE มากกว่าจำนวนกล้อง | จ่ายไฟให้กล้องผ่านสาย LAN เส้นเดียว | แนะนำ |
| UPS | 650–1000 VA สำหรับคอมและ switch | กันไฟดับและไฟกระชาก ไม่ให้ฐานข้อมูลเสีย | แนะนำ |

| ป้ายประกาศว่ามีกล้องวงจรปิด | – | แจ้งให้คนที่เข้ามาทราบ | แนะนำ |
| บัญชี Tailscale | มีแพ็กเกจส่วนตัวใช้ฟรี | ดูผ่านมือถือนอกบ้านได้อย่างปลอดภัย | ถ้าต้องการดูนอกบ้าน |

ถ้ามีกล้องวงจรปิดกับเครื่องบันทึก (NVR) อยู่แล้ว โปรแกรมดึงภาพจาก NVR ผ่าน RTSP ได้ แต่กล้องมุมกว้างที่ติดไว้ดูภาพรวมมักเห็นป้ายเล็กและเบลอตอนกลางคืน จึงควรมีกล้องอ่านป้ายแยกอย่างน้อยจุดละตัว

วิธีติดกล้องให้อ่านป้ายแม่น:

- ติดตรงจุดที่รถชะลอหรือหยุด เช่น หน้าประตูรั้ว ห่างจากป้ายประมาณ 3–8 เมตร
- ให้กล้องมองป้ายเกือบตรง มุมเอียงซ้าย-ขวาและก้มไม่เกินประมาณ 30 องศา
- ซูมจนป้ายในภาพกว้างอย่างน้อยราว 130–150 พิกเซล (ค่าประมาณ ให้ทดสอบกับรถจริง)
- อย่าหันกล้องสวนแสงแดดหรือไฟหน้ารถตรงๆ ตอนกลางคืนให้ตั้งชัตเตอร์เร็ว ป้ายจะได้ไม่สว่างจ้าจนอ่านไม่ออก
- ตั้ง IP กล้องแบบคงที่ เปลี่ยนรหัสผ่านเริ่มต้น และเปิด sub-stream ไว้ด้วย
- ลองกับรถจริงทั้งกลางวันและกลางคืนก่อนยึดกล้องถาวร

5. iPhone/iPad (Safari): กดปุ่มแชร์ แล้วเลือก เพิ่มไปยังหน้าจอโฮม

## ข้อควรรู้

ช่วงแรกระบบจะอ่านป้ายผิดบ้าง ความแม่นยำจะดีขึ้นหลังปรับมุมกล้องและฝึกโมเดลด้วยภาพป้ายจากกล้องของคุณเอง

- **ความแม่นยำ:** โมเดลอ่านภาษาไทยของ PaddleOCR (th\_PP-OCRv5\_mobile\_rec) ทำได้ 82.68% บนชุดข้อมูลทั่วไปที่ผู้พัฒนาใช้ทดสอบ ไม่ใช่ชุดป้ายทะเบียน ([PaddleOCR](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html)) prompt จึงให้โหวตหลายเฟรม ใช้คิว รอตรวจสอบ และมีสคริปต์เก็บภาพป้ายจริงไว้ฝึกโมเดลเพิ่ม EasyOCR ซึ่งรองรับภาษาไทยเช่นกันเป็นตัวสำรอง ([EasyOCR](https://pypi.org/project/easyocr/1.2))
- **กลางคืนสำคัญที่สุด:** ถ้ากลางวันอ่านได้แต่กลางคืนพลาด ส่วนใหญ่แก้ที่ตัวกล้อง (ความเร็วชัตเตอร์ IR และแสงสว่าง) ไม่ใช่ที่โปรแกรม
- **ข้อมูลส่วนบุคคล (PDPA):** ป้ายทะเบียนที่ผูกกับชื่อเจ้าของถือเป็นข้อมูลส่วนบุคคล ถ้าใช้เฉพาะบ้านตัวเองมักเข้าข่ายกิจกรรมส่วนตัว แต่ถ้าใช้ในหมู่บ้านหรือพื้นที่ส่วนกลาง ควรติดป้ายแจ้ง กำหนดระยะเก็บข้อมูล และจำกัดคนที่ดูได้ ข้อนี้เป็นข้อมูลทั่วไป ไม่ใช่คำแนะนำทางกฎหมาย
- **ความปลอดภัย:** เปลี่ยนรหัสผ่านเริ่มต้นของกล้อง อัปเดต Windows สม่ำเสมอ ห้ามเปิดพอร์ตเราเตอร์ตรงเข้าคอม และสำรองโฟลเดอร์ D:\\LPR ไว้ที่ไดรฟ์อื่นด้วย
